A test spends one real request. It is the only check that distinguishes a valid credential from an expired one — claude auth status reports a dead grant as logged in. A rejected credential can take up to two minutes to fail, because the CLI retries before giving up.

Replace the token

Generate one on this host as the service user:

claude setup-token

It prints once and the CLI saves it nowhere — that is what this form is for. Tokens last about a year and do not renew themselves.

The token is tested before it is written, so a mistyped paste cannot displace a working one. It is saved to {{ auth.token_file }} at mode 0600 and read fresh on every generation — no restart needed.

How the CLI picks a credential

In its own order of precedence:

  1. ANTHROPIC_API_KEY — bills per request. Content Forge strips this from the environment before every call so it can never quietly take over from your subscription.
  2. CLAUDE_CODE_OAUTH_TOKEN — the token this page manages.
  3. ~/.claude/.credentials.json — written by an interactive claude login. Fine on a desktop; on a service it expires and nothing renews it.
